# 设计到实现跟踪

更新日期：2026-10-25。设计来源：[设计草稿 v0.1](设计草稿v0.1.md)；项目总览与看板见 [README](../../README.md#项目进度)，验证证据见[项目状态](../development/status.md)。

本表覆盖当前草稿的机制、卡牌和遗物，按草稿分类、顺序整理。费用独立成列，效果保留草稿表述及括号内升级信息；检索短名只便于讨论，不是正式卡名。两张基础牌的数值来自现有教学实现，草稿只写了“5打5防”。草稿中的先古卡虽放在“遗物一览”下，在这里按卡牌统计。

## 状态与编号约定

| 状态 | 含义 | 应有记录 |
| --- | --- | --- |
| 未实现 | 尚无符合当前设计的实现；有相似命令、占位卡或机制参考也不算已实现 | 设计、依赖／待确认项；无代码填“—”，待调整的旧代码保留链接并注明差异 |
| 进行中 | 已实际开工，代码或配套内容尚未完成 | 已有代码／工作分支、剩余工作；README 看板同步移入进行中 |
| 已实现 | 当前条目的效果、升级、注册和必要本地化已落地，相关源码／构建检查通过 | 稳定模型 ID、真实源码链接；实机结果单独记录 |

“已实现”不代表已通过完整爬塔、平衡或联机验收。当前三张已实现卡有[历史基础实机记录](../development/status.md#验证记录)；未实现条目均未做对应实机验证。本次仅整理文档，没有新增玩法实现。

- 设计编号用于跨草稿追踪；已有的 `HS-BASE-001/002`、`HS-TOKEN-001` 保持不变。本次为其余条目首次编号，之后调整名称、顺序或稀有度均不重编号、不复用删除项的编号。
- 设计编号与游戏模型 ID 是两回事。未实现项暂不分配模型 ID，也不创建占位源码；实现时登记实际 `CustomID`。
- `HS-ATK`／`HS-SKL`／`HS-POW` 分别表示攻击／技能／能力，编号跨稀有度连续；`HS-START` 表示特殊初始牌，`HS-ANCIENT` 表示先古相关卡。
- 普通／罕见／稀有沿用草稿白／蓝／金分类。括号内为升级效果；未写升级或带问号的条目保留原状，见 [Q8](#q8)。
- 表中的依赖与疑问是开发提示，不是新增玩法规则；共用语义以[机制参考](../../.agents/skills/sts2-heavysilent-dev/references/mechanics.md)及后续策划确认为准。

## 日常维护

1. 策划修改[草稿](设计草稿v0.1.md)后，按编号同步本表的分类、费用、效果和疑问。移动条目保留编号；新增用该编号系列的下一个未用号码；删除项保留编号及撤销说明，移出当前统计。
2. 开始实现时将条目标为“进行中”，登记已有代码与剩余工作，并把 [README 看板](../../README.md#开发看板)中的对应任务移入进行中。仅排期或讨论仍是“未实现”。
3. 实现完成后登记实际模型 ID、源码和验证结果。代码位置使用文件链接，不维护易失效的行号；实机结论与证据写入[状态页](../development/status.md)，没有测试就明确写未验证。
4. 同一次交付刷新本表统计和 README 汇总，更新看板及相关机制说明。设计改动使既有代码不再满足条目时，状态退回“进行中”（已着手调整）或“未实现”（待调整），保留旧代码链接并说明差异。
5. 本表手动维护，没有运行时读取或自动同步。提交前核对草稿覆盖、编号唯一性、分类计数及源码链接，并运行 `python scripts/verify.py` 检查本地文档链接、内容 ID 与本地化；该命令不检查草稿与表格的语义一致性。
