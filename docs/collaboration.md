# 人类与 Agent 协作

这里是人类与 Agent 的协作 Issue 入口，属于开发脚手架。Q&A 是 Issue 的沟通格式；设计决策回答“应该怎样做”，Review 核对“交付是否符合要求”。两类 Issue 都进入人类待办，但不与代码的“未实现／进行中／已实现”混为一谈。本页维护活动事项，已关闭事项移入[归档](#已关闭-issue-归档)。

在 Codex CLI 中尚未得到答案、需要保留到后续会话的问题都可以登记，包括玩法、需求、命名与素材、开发环境、任务范围和验收反馈。技术上能由 Agent 查证的事项先由 Agent 调查，确实需要人类选择或提供信息时才进入“待人类”。

## 如何回答

1. 从下方任务表打开条目，在 **A／人类回答** 中直接写答案即可；可以只答已确定的子项，不必一次答完。
2. 也可以在 CLI 中回复“Q1.1：……；Q1.2：……”，或“R1：通过／需要修改／暂缓，理由是……”。Agent 将回答和来源日期写回同一条目。已经明确回答过的内容不重复询问。
3. 不确定时写“暂缓，等……再决定”；需要分析时写“请 Agent 比较……”。无需为了填表立即作决定。
4. 告诉 Agent“处理协作文档中的新回答”。你不需要维护状态、设计正文或看板；Agent 接手时也应主动检查新回答，而不只看表内状态。

活动 Issue 的问题正文、回答与处理记录只在本页维护；关闭后完整迁入 `docs/collaboration/archive/`，本页及其他文档仅保留归档索引。确认后的当前玩法仍写入[对应设计文档](design/README.md)，工程约定写入相应技术参考；协作记录保留决策来源与落点链接，不作为另一份持续维护的规则文档。

### 状态与维护

| 状态 | 含义与下一位处理者 |
| --- | --- |
| 待人类 | Agent 已整理问题或可 Review 的结果，等待回答、选择或评审 |
| 待 Agent | 已有回答待整理、意见待修改，或需要 Agent 补充调查／证据 |
| 暂缓 | 人类明确要求延期；记录原因和恢复条件，问题仍未解决 |
| 已关闭 | 问题已得到答案并写回正式文档，或明确撤销；Review 已有人类结论且相关修改已处理。Agent 在同次交付中归档 |

- 问题沿用 Q 编号，评审沿用 R 编号；均为 Issue，不因统一称谓而重编号。分配新编号时同时检查活动列表与归档，目前下一个为 Q9／R2。一个主题可有 Q1.1 这样的子项，不能复用已关闭编号。
- 部分回答保留在原条目，标明仍未回答的子项。Agent 可先落实已明确的独立部分；不能把未回答项、建议或测试通过当作人类同意。
- CLI 已有明确答案时直接记录来源和结论，不再建一个“待人类”事项求重复确认。存在冲突或答案仍影响当前实现时，明确剩下的具体问题。
- Agent 收到回答后记录自己的理解及处理结果，更新设计／技术正文和相关看板，再关闭已解决的 Issue，并在同次交付中归档。关闭设计问题不代表已实现卡牌或机制；部分回答、暂缓和仍待 Review 的事项继续留在活动列表。
- Review 指定提交或文件、核对点、验证证据和未测范围；先把结果做到可评审，再交给人类。需要修改则由 Agent 处理，必要时带新证据回到同一 R 条目复审。执行已授权任务和创建本地提交不以额外 Review 回复为前提。
- 归档完整保留问题、原回答、补充修正和处理记录，记录关闭／归档日期及正式文档落点；按日期和编号范围存入 `docs/collaboration/archive/YYYY-MM-DD-qN-qM.md`，Review 可用对应 R 编号。迁移时修正相对链接，本页保留原编号与补充回答锚点作为入口；不得仅删除正文或等待积累后才归档。
- 归档记录作为历史来源保留；后续有新问题或推翻原结论时，新建 Issue 并链接原记录，确认后更新正式设计。README 已处理栏链接归档，活动列表仅列未关闭事项。

## 新增条目模板

按实际需要填写，不必为没有问题的任务建空项。Q 用于问题与决策，R 用于具体交付的评审；技术调查可以由 Agent 发起并处理。使用前核对活动及归档编号，关闭后按上方约定归档。

```markdown
<a id="q9"></a>

## Q9 · 简短主题（Review 使用下一个 R 编号）

- 类型：设计决策／需求沟通／资料或环境／技术调查／Review
- 状态：待人类／待 Agent／暂缓／已关闭（同步上方任务表）
- 关联：设计条目、开发任务、文件或提交
- 影响与时机：哪些工作依赖答案，哪些可继续

**Q／问题：** 说明上下文与需要回答的具体事项；必要时提供方案及取舍。
Review 在这里列明交付对象、核对点、证据和未测范围。

**A／回答或评审意见：** 待填写。

**Agent 处理记录：** 回答来源／日期、理解、处理结果、正式文档落点及剩余事项。

**关闭／归档记录：** 关闭日期、归档日期和归档位置；尚未关闭时不填写完成日期。
```

Review 的具体检查方法见[Review 指引](development/review.md)，开发排期见 [README 看板](../README.md#开发看板)。
